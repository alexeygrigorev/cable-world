# Агенты проекта

## orchestrator

Отвечает за смысл и порядок работы.

Обязанности:

- переводит запрос владельца проекта в GitHub Issue;
- фиксирует критерии готовности;
- назначает implementer и reviewer;
- следит, чтобы одновременно интегрировалась только одна reviewed-задача;
- не принимает архитектурные расширения без связи с MVP.

## implementer

Отвечает за рабочие изменения.

Обязанности:

- работает в worktree конкретного Issue;
- держит правки в границах задачи;
- сохраняет пользовательские тексты на русском;
- добавляет или обновляет быстрые проверки;
- не добавляет тяжелые зависимости и бинарники без отдельного решения.

## reviewer

Отвечает за качество результата.

Обязанности:

- проверяет соответствие Issue;
- ищет регрессии, риски данных и слабые места UX;
- запускает обязательные проверки;
- для UI-задач запускает приложение и сохраняет скриншоты как минимум в портретном мобильном размере `390x844` и горизонтальном мобильном размере `844x390`;
- для карты отдельно проверяет, что область карты не пустая, маркеры видны, а управление пригодно для пальца;
- для object mode отдельно проверяет скриншоты `390x844` и `844x390`, читаемость, tap targets, скролл или панорамирование, возврат назад, пустые состояния и похожесть объекта на реальный;
- ставит object mode `ACCEPT`, только если объект визуально похож на реальный транспортный или инженерный объект, текст читается в обеих ориентациях, основные tap targets пригодны для пальца, скролл или панорамирование не ломают выбор, возврат назад работает, пустые состояния понятны на русском и приложены оба скриншота;
- ставит object mode `REJECT`, если нет хотя бы одного скриншота `390x844` или `844x390`, текст обрезан или не читается, tap targets слишком мелкие, скролл или панорамирование конфликтуют с выбором, нельзя вернуться назад, пустое состояние непонятно или объект выглядит как абстрактная заглушка вместо реального объекта;
- требует доработки до интеграции, если контракт задачи не выполнен;
- пишет явный вердикт `ACCEPT` или `REJECT`; без `ACCEPT` UI-задача не идет в релиз;
- документирует остаточные риски.
