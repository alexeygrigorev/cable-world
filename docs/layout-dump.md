# layout_dump.gd — Текстовый дамп layout'а для анализа без скриншотов

## Запуск

```bash
godot --headless --script res://tmp/layout_dump.gd --path .
```

Вывод: stdout + файл `tmp/layout_dump.txt`.

## Что делает скрипт

Загружает сцену Main.tscn, для каждого размера viewport'а (мобильный 390x844, ландшафт 844x390) обходит всё дерево Control-узлов и для каждого показывает:

- `[V-]` — видим, `[H-]` — скрыт (visible = false)
- `[VC]` — видим + clip_contents включён
- `pos=(x, y)` — локальная позиция относительно родителя
- `size=(w, h)` — фактический размер после layout
- `min=(w, h)` — вычисленный минимальный размер
- `custom_min=(w, h)` — заданный вручную minimum_size
- `global: (x, y) -> (right, bottom) [W x H]` — экранные координаты
- `*** CLIPPED` — элемент обрезается родителем, ~X% площади скрыто
- `*** ZERO SIZE` — элемент видим но имеет нулевой размер
- `Overlapping children` — видимые дети одного родителя пересекаются

## Как интерпретировать

### CLIPPED в ScrollContainer — норма

Если родитель — ScrollContainer и ребёнок CLIPPED, это ожидаемо:
контент прокручивается. Но если видимый процент маленький
(< 30%), начальный вид показывает мало полезного контента.

### CLIPPED НЕ в ScrollContainer — баг

Если обычный Control или PanelContainer обрезает ребёнка,
часть UI буквально невидима без возможности скролла.

### Overlapping children — может быть проблемой

Абсолютно позиционированные элементы (как контролы карты) могут
перекрывать контент. Если overlap не задуман — это визуальный баг.

### ZERO SIZE — баг

Видимый элемент с size = (0, 0) не отображается. Обычно означает
отсутствие данных (как в headless без SQLite) или ошибку layout.

## Текущие проблемы (найдены через дамп)

### 1. Map: контролы перекрывают канву карты

`МасштабКарты` (+/-/Вписать) и `ФильтрКарты` абсолютно
позиционированы внутри `ТочкиОбъектов` и перекрывают
`ПодвижнаяКарта` (маркеры и географию).

```
Overlapping children:
  'ПодвижнаяКарта' <-> 'МасштабКарты' overlap: (761, 208, 48 x 160)
  'ПодвижнаяКарта' <-> 'ФильтрКарты' overlap: (27, 208, 168 x 48)
```

Решение: вынести контролы из map_layer в отдельный toolbar
под картой.

### 2. Landscape: карта обрезана на 35%

Viewport 844x390, содержимое Секции = 35% скрыто.
MapPanel занимает 276px, но видимая область ContentScroll = 229px.
SelectedObjectLabel уходит за экран (y=476 при viewport bottom=378).

Решение: уменьшить высоту карты в ландшафте, адаптировать
_sync_map_canvas_height.

### 3. ContentScroll вылезает за ContentViewport (~1-2%)

ContentScroll позиционируется на (-3, 0) и на ~2% выходит
за bounds ContentViewport. Мелкая проблема, но может вызывать
артефакты скролла.

### 4. ObjectMode: GridContainer station_buttons = ZERO SIZE

В headless режиме нет SQLite, демо-каталог не содержит stations.
Это не баг игры, а ограничение дампа. При реальных данных
кнопки станций должны отображаться.

### 5. Маркеры карты перекрываются

Некоторые маркеры накладываются друг на друга (3 пары):
```
Маркер3 <-> Маркер20 overlap: (15 x 41)
Маркер7 <-> Маркер34 overlap: (17 x 29)
Маркер14 <-> Маркер34 overlap: (14 x 7)
```

Алгоритм _spread_marker_position не всегда находит свободное место.
