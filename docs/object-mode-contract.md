# Контракт Object Mode

Документ фиксирует минимальный data contract для object mode: режима, в котором семья открывает выбранный реальный объект и видит его узнаваемую схему, станции, направление поездки, маршрутные отрезки, материалы и инженерные точки. Контракт нужен для #38 и не требует нового UI, новой миграции, релиза, export presets или изменения seed SQL.

## Граница режима

Object mode всегда открывается из выбранного `TransportObject`. Он не создает отдельный объект каталога, не подменяет общую карту и не хранит свою копию названия, координат, статуса посещения или эксплуатационного статуса.

Переход данных:

1. выбранный `TransportObject` задает `transport_object_id`, заголовок объекта, тип транспорта, координату на общей карте и семейный статус;
2. детальная схема загружает дочерние `ObjectStation`, `RouteDirection`, `RouteSegment`, `EngineeringPoint` и связанные `MediaAsset`;
3. пользователь выбирает станцию, направление, отрезок или инженерную точку внутри схемы;
4. режим поездки запускается только из выбранного `RouteDirection` и показывает путь от начальной станции к конечной через упорядоченные `RouteSegment`.

Общая карта остается уровнем каталога: один `TransportObject` равен одной точке. Object mode является внутренним представлением выбранного объекта и строится из данных модели, а не из случайной схемы, UI hardcode или генерации станций на клиенте.

## Обязательные данные

Минимальный object mode payload для выбранного объекта:

- `transport_object_id` - стабильная ссылка на корневой `TransportObject`;
- `object` - display-данные объекта: `id`, `title`, `transport_type_id`, `operational_status`, `visit_status_id`, `latitude`, `longitude`;
- `stations` - список `ObjectStation`, отсортированный по `sort_order`;
- `route_directions` - список `RouteDirection`, отсортированный по `sort_order`;
- `route_segments_by_direction` - отрезки `RouteSegment`, сгруппированные по `route_direction_id` и отсортированные по `segment_order`;
- `engineering_points` - список `EngineeringPoint` или пустой список, если инженерные точки еще не добавлены;
- `media_assets` - материалы объекта, станции, направления или отрезка через `MediaAsset.station_id`, `MediaAsset.route_direction_id`, `MediaAsset.route_segment_id`.

### ObjectStation

Станция, платформа или важная точка выбранного объекта.

Обязательные поля:

- `id` - стабильный ASCII id, пригодный для i18n, импорта, тестов и ссылок из медиа;
- `transport_object_id` - ссылка на выбранный `TransportObject`;
- `title` - русское display-название станции;
- `station_role` - роль станции или платформы, например нижняя, верхняя, промежуточная, сервисная или `unknown`;
- `sort_order` - порядок показа на схеме;
- `note` - русская подпись или пустая строка.

Координаты `latitude` и `longitude` опциональны. Если они есть, схема может расположить станцию ближе к реальной географии. Если координат нет, UI использует порядок и связи маршрута, но не придумывает случайные станции.

### RouteDirection

Направление поездки внутри выбранного объекта.

Обязательные поля:

- `id` - стабильный ASCII id, пригодный для i18n и deep link внутри object mode;
- `transport_object_id` - ссылка на выбранный `TransportObject`;
- `from_station_id` - начальная `ObjectStation`;
- `to_station_id` - конечная `ObjectStation`;
- `title` - короткая русская подпись направления;
- `direction_label` - человекочитаемая русская фраза, например «от Киенбергпарка к Садам мира»;
- `sort_order` - порядок выбора направления;
- `note` - русская заметка или пустая строка.

`from_station_id` и `to_station_id` должны ссылаться на станции того же `transport_object_id`. Object mode не должен строить поездку между станциями разных объектов.

### RouteSegment

Отрезок маршрута внутри направления.

Обязательные поля:

- `id` - стабильный ASCII id;
- `transport_object_id` - ссылка на выбранный `TransportObject`;
- `route_direction_id` - ссылка на `RouteDirection`;
- `from_station_id` - начальная станция отрезка;
- `to_station_id` - конечная станция отрезка;
- `segment_order` - порядок отрезка внутри направления;
- `title` - русское название отрезка;
- `direction_label` - русская подпись движения, например «вверх к Волькенхайну»;
- `note` - русская заметка или пустая строка.

Сегменты образуют маршрут поездки. Режим поездки читает их из данных, а не хранит названия станций или порядок движения в UI-коде.

### EngineeringPoint

Инженерная точка или hotspot на схеме выбранного объекта.

Обязательные поля будущей модели:

- `id` - стабильный ASCII id, пригодный для i18n и ссылок из медиа;
- `transport_object_id` - ссылка на выбранный `TransportObject`;
- `title` - русское display-название точки;
- `point_type` - тип точки: двигатель, редуктор, приводное колесо, натяжное колесо, опора, поворотный узел, обзорная точка, hotspot или `unknown`;
- `station_id` - опциональная ссылка на `ObjectStation`, если точка относится к станции;
- `route_segment_id` - опциональная ссылка на `RouteSegment`, если точка относится к участку маршрута;
- `sort_order` - порядок показа в списках и подсказках;
- `note` - короткое русское объяснение.

`EngineeringPoint` связывает инженерный режим, прогулку и object mode с той же схемой объекта. Если точек нет, object mode показывает пустое состояние и не заменяет их случайными hotspot.

## Пустые состояния

Пустые данные являются допустимым состоянием, а не ошибкой базы.

- Нет выбранного `TransportObject`: показать «Объект не выбран» и предложить вернуться к списку или карте.
- Нет `ObjectStation`: показать «Для этого объекта пока нет станций схемы».
- Нет `RouteDirection`: показать «Для этого объекта пока нет направления поездки».
- Нет `RouteSegment` для выбранного направления: показать «Для этого направления пока нет отрезков маршрута».
- Нет `EngineeringPoint`: показать «Инженерные точки для этого объекта пока не добавлены».
- Нет материалов для станции, направления или сегмента: скрыть блок материалов или показать «Для этого места пока нет материалов».

Пустые состояния должны быть на русском. Они не должны менять `visit_status_id`, `operational_status`, данные маршрута или пользовательские материалы.

## I18n-Ready Идентификаторы

Все id в object mode остаются стабильными ASCII-идентификаторами: `TransportObject.id`, `ObjectStation.id`, `RouteDirection.id`, `RouteSegment.id`, `EngineeringPoint.id`, `MediaAsset.id`. Эти id не переводятся, не строятся из текущего UI-языка и не меняются при переименовании русской подписи.

Пользовательский текст хранится отдельно в display-полях: `title`, `direction_label`, `note`, `caption`, `geo_note`. Для будущей локализации id останутся ключами, а русские строки смогут стать значениями переводов или локализованными полями.

## Вертикальный Срез Berlin

`berlin-gaerten-der-welt` является главным вертикальным срезом object mode. Он нужен, чтобы проверить всю цепочку выбранный `TransportObject` -> детальная схема -> станция -> поездка без случайных данных и UI hardcode.

Для этого вертикального среза обязательны:

- `TransportObject.id = berlin-gaerten-der-welt`;
- три `ObjectStation`: Киенбергпарк, Волькенхайн и Сады мира;
- два `RouteDirection`: от Киенбергпарка к Садам мира и от Садов мира к Киенбергпарку;
- минимум два `RouteSegment` для направления `berlin-gaerten-der-welt-direction-kienbergpark-to-gaerten`;
- русские `title`, `direction_label`, `note`, `caption` и `geo_note` для пользовательского UI;
- демо-видео или другой `MediaAsset`, связанный с направлением, станцией или отрезком;
- отсутствие hardcode названий станций и маршрута в object mode UI: названия должны приходить из `ObjectStation`, `RouteDirection` и `RouteSegment`.

Если будущая реализация добавит `EngineeringPoint` для этого объекта, она должна ссылаться на тот же `transport_object_id` и, где возможно, на существующие станции или сегменты. Отсутствие инженерных точек пока не блокирует object mode, но контракт пустого состояния должен сохраняться.
