# V3 контракт режимов поездки и наблюдателя

Документ фиксирует требования и минимальный data/UI contract для V3-режимов «поездка» и «наблюдатель». Это post-1.0 roadmap: для цели 1.0 эти режимы не являются blocker, если текущий MVP уже показывает выбранный маршрут в карточке объекта через станции, направления и 2D-схему.

Контракт не реализует полноценный 3D, физическую симуляцию каната, движение кабины в реальном времени или отдельную игровую сцену. V3-режимы должны быть будущим слоем поверх существующей модели, а не заменой MVP-карты.

## Общая граница

Оба режима запускаются только из выбранного `TransportObject`. Общая карта остается 2D-картой объектов: она показывает координату объекта, список и статус посещения. Детальная карточка объекта остается текущим MVP-местом, где семья видит станции и схему маршрута.

V3-режимы должны использовать те же данные, которые уже читает карточка объекта:

- `transport_object_id` - корень выбранной линии или инженерного объекта;
- `object_stations` / `ObjectStation` - станции, платформы и важные точки посадки;
- `route_directions` / `RouteDirection` - направление поездки между начальной и конечной станцией;
- `route_segments` / `RouteSegment` - упорядоченные отрезки маршрута внутри направления;
- `media_assets` / `MediaAsset` - фото, видео и документы, привязанные к объекту, станции, направлению или отрезку.

Если у объекта нет `RouteDirection` или `RouteSegment`, режимы не должны ломать MVP. UI показывает русское пустое состояние и предлагает вернуться к карточке объекта. Для цели 1.0 достаточно, что карточка уже показывает «Схема маршрута» и маршрутные подписи по существующим данным.

## Режим поездки

Режим «поездка» показывает движение по выбранному `RouteDirection` от `from_station_id` к `to_station_id`. Он не обязан быть 3D-симуляцией: минимальный V3 UI может быть 2D-проигрывателем маршрута поверх детальной схемы объекта.

Минимальный data contract:

- вход: выбранный `transport_object_id` и выбранный `route_direction_id`;
- направление берется из `route_directions`, включая `title`, `direction_label`, `from_station_id`, `to_station_id` и `sort_order`;
- этапы поездки берутся из `route_segments`, отфильтрованных по `route_direction_id` и отсортированных по `segment_order`;
- названия станций берутся из `object_stations` по `from_station_id` и `to_station_id`;
- медиа в контексте поездки берутся из `media_assets`, где совпадает `route_direction_id`, `route_segment_id` или связанный `station_id`;
- все видимые подписи строятся на русском display text: `title`, `direction_label`, `note`, `caption`, `geo_note`.

Минимальный UI contract:

- заголовок режима: «Поездка»;
- направление: русская подпись из `RouteDirection.direction_label`, например «от Киенбергпарка к Садам мира»;
- этапы: список или дорожка `RouteSegment` с русскими подписями вроде «вверх к Волькенхайну» и «вниз к Садам мира»;
- медиа: блок «Материалы поездки» для фото или видео, связанных с направлением, отрезком или станцией;
- возврат: команда «К карточке объекта», которая не меняет данные маршрута и не сбрасывает MVP-статус посещения.

При отсутствии направления UI показывает: «Для этой поездки пока нет направления маршрута». При отсутствии сегментов UI показывает: «Для этого направления пока нет отрезков маршрута». Эти состояния не являются ошибкой базы и не блокируют 1.0.

## Режим наблюдателя

Режим «наблюдатель» показывает внешний обзор объекта, маршрута, станций, опор и кабины без управления поездкой. В V3 это может быть 2D-обзор или простая будущая сцена, но она должна оставаться представлением выбранного `TransportObject`.

Минимальный data contract:

- вход: выбранный `transport_object_id`;
- линия и станции берутся из `object_stations`, `route_directions` и `route_segments`;
- обзор строится от объекта в целом, поэтому `route_direction_id` опционален;
- если направление выбрано, кабина или маркер движения используют порядок `route_segments.segment_order`;
- опоры и инженерные детали в текущей модели могут быть подписаны через будущий `EngineeringPoint`, но их отсутствие не ломает режим;
- медиа объекта и станций могут показываться как справочные материалы внешнего обзора.

Минимальный UI contract:

- заголовок режима: «Наблюдатель»;
- общий обзор: русские подписи станций и линии выбранного объекта;
- кабина: визуальный маркер или подпись «кабина» на маршруте без ручного управления поездкой;
- опоры: русские подписи «опора» там, где данные уже есть или будут добавлены через `EngineeringPoint`;
- возврат: команда «К карточке объекта».

При отсутствии маршрутных данных UI показывает: «Для наблюдения пока нет схемы маршрута». При отсутствии инженерных точек UI не показывает ошибку: опоры являются V3-расширением, а не обязательством 1.0.

## Связь с MVP

V3-режимы не требуют изменений в `VERSION`, export presets или release workflow. Они не должны менять смысл существующих таблиц и не должны требовать новой миграции только для запуска пустого режима.

Существующая 2D-карточка объекта остается baseline:

- `scripts/main_screen.gd` уже обогащает выбранный объект через `list_object_stations`, `list_route_directions` и `list_route_segments`;
- `scripts/object_card_panel.gd` уже показывает станции и «Схема маршрута»;
- `scripts/storage/migrations/003_media_geo_routes.sql` уже содержит таблицы и связи для станций, направлений, отрезков и медиа;
- `scripts/storage/seeds/demo_objects.sql` уже содержит демонстрационный маршрут `berlin-gaerten-der-welt`.

Поэтому #31 и #33 после этого документа считаются покрытыми на уровне design/contract. Полная реализация запуска режимов, визуального проигрывания поездки, маркера кабины, опор и будущей сцены остается отдельной V3 implementation work и не должна блокировать 1.0.

Иными словами: V3-контракт нужен, чтобы не блокировать 1.0 и не ломать текущий MVP ради преждевременной сцены.
